本文 Skill 只回答一件事：怎样从文章内容与已选模板，生成清楚、准确且适合手机阅读的完整图片。

---

# 先确认模板，再确认用途

每次新任务按这两个顺序补齐缺失信息，已明确的信息不重复问。

1. 模板未知时问：「你现在使用的是哪一个模板？请告诉我模板名称，我来为你生成对应的图片。」
2. 模板明确后，用途未知时问：「你要生成的是封面图，还是某一段文章的配图？」

用户已经说「用简笔手绘做这篇文章的封面」，直接进入封面制作。
用户只说「做张公众号图」，先问模板，不能先猜画风或先出默认封面。
用户说「配图」却没有段落，接着请他给出需要说明的段落；拿到全文时可先提出一个确有理解价值的位置。
如果明确要头图，按轻量横向场景处理，不把文章封面自动当头图。

运行 `scripts/route_theme.py list` 可列出可选模板。
名称相似或未知时展示匹配候选让用户选择，不把目录编号当作永久主题身份，不静默改用第一套。

# 最小读取顺序

1. 当前文章或目标段落与用户指定的准确图中文字。
2. [配图规则](references/配图规则.md)。
3. 用路由脚本解析模板，只读返回的该主题简要规则。
4. 用户指定模板包或 Vault 时，读取该主题当前 `manifest.json`、字体映射与对应封图或配图规范；本 Skill 的公共信息、少字与一体生图约束优先于历史案例的固定结构。
5. 只有用户要复现、或确实缺少风格依据时，才看一两张相关案例。不加载全部历史提示、十个模板正文或开发日志。

```bash
python3 scripts/route_theme.py list
python3 scripts/route_theme.py resolve 简笔手绘 --kind cover --project /path/to/obsidian-wechat-mp
python3 scripts/route_theme.py resolve dune-echo --kind illustration --vault /path/to/YourVault
python3 scripts/route_theme.py resolve 简笔手绘 --kind cover --templates /path/to/templates
```

支持仓库的 `templates/<theme_id>/`、插件安装目录内的 `templates/`，也支持开发者指定的主题库目录。
未提供路径时先找与当前 Skill 同仓库的 `templates/`，否则使用自带的精简视觉规则。
模板资料均通过相对路径与 `theme_id` 定位，不要求新用户复制开发者的 Vault 结构。
没有读到实际字体文件时，只能称为字形方向，不能声称已精确使用某个字库。

# 先做信息选择，再做画面

用几行简报明确：用途、源段落、一句话阅读目标、准确图中文字、核心关系、画幅、主题、H1/H2 字形和参考图职责。
从段落提炼短标签可以压缩信息，但不得编造结论、步骤、数字、因果或人物事实，也不得改动原文章文件。
用户指定逐字保留的标题与数字不能自行改短；放不下就减少其他信息或调整构图。

封面只保留一个第一阅读点。
主标题优先简短、直观，通常从 6—12 个汉字起步；这不是删字配额。
副标题、英文、作者名和装饰标签都不是必需元素，只有带来必要信息时才加入。

段落图先选关系：一个概念、一次对照、一个流程或一组有依据的数量。
第一层是一句主结论或核心关系，第二层是少量短标签；长解释留在正文。
不能靠把字缩小、套满卡片或重复原文来容纳信息。
真实截图与证据照保留事实；精确数据图使用可核对的绘图工具，不生造界面或数据。

# 字体与一体生图

主标题采用所选主题 H1 的字形语言，次级标题采用 H2，说明文字采用该主题清楚可读的辅助字形。
如果 `manifest.json` 中有真实字体，优先用实际字形参照；公共发行包的 manifest 优先于开发者旧记录。

需要字形样张时可执行：

```bash
python3 scripts/font_reference.py --font /path/to/font.ttf --text '把时间还给创作' --output /path/to/font-reference.png
```

这个输出只供模型看字形，不是最终底图或后期文字层。
样张可与主题纹理、风格参考一起交给图像生成工具；准确文案、全部层级和画面在同一次生成里完成。
不能先生成无字底图，再用 Pillow、HTML、Canvas、SVG 或设计软件往成品叠字。
字库参考可提高方向一致性，但生成模型未必逐字复现字库轮廓；验收时如实区分准确字形与近似风格。

使用当前环境可用的图像生成工具；有相关生图 Skill 时按其工具要求调用，但不继承与所选主题冲突的默认风格。
参考 [完整图文提示结构](references/完整图文提示结构.md)，把准确文字、空间关系与禁止项一并交给模型。
错字、漏字、乱码、形体错误、关系错误或关键遮挡，修改提示重新生成整图；不通过后期叠字掩盖。
生成工具不可用时保存完整简报和提示，明确标为待生成，不能把提示词当成已交付图片。

# 手机阅读与交付

封面默认按项目约定分别生成 2.35:1 宽图与 1:1 方图；用户只要一种时尊重其范围。
两张独立安排主体和标题，不能直接裁掉宽图的重点。
普通封面不堆模块；头图和模板介绍大图只有在用户要求时制作。

封面底部两角先留作角标保护区，不放必读文字、人脸或关键道具。
这是一项保守设计，不是关于微信固定角标位置的官方断言；当前入口、客户端与裁切仍需实际核对。
详细检查见公共规则中的「缩图与遮挡」。

交付前逐字校图，再按宽封面约 300px、方封面约 128px、正文图 390px 与 320px 检查。
实际看不清时减少文字或重新构图，不把「原图很清晰」作为通过理由。

保存采用图片、完整提示与简报，文件名区分用途、比例和版本，候选不覆盖已选成品。
按当前文章附件约定落盘；用户明确要求模板样例时才放到该模板的展示位置。
在 Obsidian 中只同步规则、图片及必要引用，不创建 Skill 副本；共享 Skill 实体由安装环境管理。
插图和规则同步后重新打开检查链接，不能仅凭写入成功报告完成。

本地审阅、公众号裁切、粘贴、保存重开与手机显示是不同验收阶段，分别记录。
不自动发布，不擅自上传参考图片到无关外部服务。
