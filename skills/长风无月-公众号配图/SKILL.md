本文 Skill 只回答一件事：怎样把文章信息按所选模板，生成准确、有层次、适合手机阅读的完整图片。

产物统一称「文章封图」；用户说「封面」或「封面图」时按同一用途识别。

---

# 总路由：只补齐缺失信息

按模板、用途、内容关系的顺序判断，已知信息不重复询问。

1. 模板未知时问：「你现在使用的是哪一个模板？请告诉我模板名称，我来为你生成对应的图片。」
2. 模板明确、用途未知时问：「你要生成的是文章封图，还是某一段文章的配图？」
3. 已知用途但缺文章或段落时再补内容；拿到全文时先找图片能帮助理解的位置，不为凑图硬选段落。

已明确要求头图时按头图范围处理，不把文章封图自动当头图。
用户要求模板介绍或能力展示时，直接进入 `references/模板展示规范.md` 的工作单，不缩成封图/配图二选一。
名称未知或不唯一时展示候选，不猜默认模板，不把目录编号当作永久身份。

```bash
python3 scripts/route_theme.py list
python3 scripts/route_theme.py resolve 简笔手绘 --kind cover --project /path/to/obsidian-wechat-mp
python3 scripts/route_theme.py resolve dune-echo --kind illustration --templates /path/to/templates
python3 scripts/route_theme.py resolve 简笔手绘 --kind illustration --vault /path/to/YourVault
```

支持仓库或插件中的 `templates/<theme_id>/`，也支持明确指定的开发主题目录。
未提供路径时先找同仓库的 `templates/`，否则使用自带风格参考。
所有正文配图均用 `--kind illustration`，概念、流程、对照、总结/检查或轻量转场写进简报。

# 公共排版先于模板风格

按以下顺序工作；通用排版只在公共参考中维护，十份模板参考只负责视觉差异。

1. 读当前内容与准确图中文字，列出需要保留的标题、步骤、短解释、数字及条件。
2. 读 [信息层级与排版.md](references/信息层级与排版.md)：明确阅读目标，安排 L1 主结论、L2 分组标签、必要的 L3 短解释，再选择关系、网格与阅读路径。
3. 读 [配图规则.md](references/配图规则.md)：确认用途、比例、事实边界与手机验收。
4. 调用路由，只读所选主题的 `visual_guide`；有实际模板包时读取当前 manifest 的字体映射与文件，不默认加载十个模板或历史开发记录。
5. 将所选主题的风格写成四项约束：媒材怎样成形、疏密与留白怎样分配、细节画到哪里停止、允许哪些主体。
6. 按 [完整图文提示结构.md](references/完整图文提示结构.md) 将这四项连同文字与布局装入完整提示，生成前逐项核对，不能只填色值和字体名。

同一内容切换模板时，保留准确文字、信息层级与关系，再按该模板调整媒材、疏密、细节、允许主体、颜色与字形。
主体、人物与留白比例按所选主题和本次用途决定，不给十个主题统一套人物场景，也不把个别主题的无人物约束扩散到其他主题。
若任务或内容关系变化，再重新选择布局。
已有模板长文或历史案例与公共信息层级冲突时，不沿用其固定卡片、少字配额或历史画幅。
风格依据不足时补看一两张原始素材，并标明只借媒材、疏密或形体；原头图和组件不自动成为新封图、正文配图的场景模板。
有文字图片的文字也占构图面积；先减少插画与装饰，不能为了达到主题留白要求缩小必要文字。

# 字体与一体生图

主结论对应主题 H1，分组标题对应 H2，短解释使用清楚可读的辅助字形。
有真实字体时，以本次实际使用的模板 manifest 和字库为准；没有实际文件时只能称字形方向。

```bash
python3 scripts/font_reference.py --font /path/to/font.ttf --text '把时间还给创作' --output /path/to/font-reference.png
```

字体样张供模型参考，不是后期文字层。
模型绘字不等于字库排字，即使提供真实字形参照，也不能声称生成文字逐点等同于该字体。
把准确文字、层级、阅读路径和画面一次交给图像生成工具，不能先出底图再用 Pillow、HTML、Canvas、SVG 或设计软件往成品叠字。
错字、漏字或关系错误回到提示，整图重生成。

有相关生图 Skill 时遵守其工具要求；信息图以文字与关系组织为先，不把影视镜头、人物动作或故事场景强加给流程图。
只在确需人物或场景解释时检查动作、空间与对象关系，不让装饰挤占必要信息。
工具不可用时保存完整简报和提示，明确标为待生成。

# 按用途验收和交付

文章封图分别按横版 2.35:1、方版 1:1 构图；用户只要一种就只做一种。
本项目正文配图统一 16:9，只有用户明确要求其他比例时才改变。
内容太密时减装饰、调整层级或拆图，不允许 Agent 自行改成 1:1、3:1 或其他比例；历史案例画幅不能作为改比例的依据。
不机械让每篇文章各配四张，也不把所有信息排成三张卡片。

逐字校图，逐项核对媒材、疏密与留白、细节上限、允许主体，再按横封约 300px、方封约 128px、正文图 390px 与 320px 实看。
文字必要且读得清时可以保留更多信息；看不清时先改善层级、空间或拆图，不删除关键条件来换空旷。
封图底部双角采用公共规则的保守留白；角标位置与裁切以当前入口实测为准。

保存采用图片、源段落、准确文字清单、简报和提示，文件名区分用途、比例与版本；候选不覆盖已选图。
按文章附件约定落盘，只有模板样例才放明确的展示位置。
涉及 Obsidian 时同步规则、图片和必要引用，不创建 Skill 副本，写后核对文件和链接。
本地审阅、公众号裁切、保存重开与手机显示分阶段记录；不自动发布或上传到无关服务。
