本文档只回答一件事：怎样验证并发布一个完整、可复现的插件版本。

---

# 本地检查

在 `plugin/` 目录执行：

```bash
npm ci
npm run check
npm run package
```

检查包括自动测试、10 套公开模板的文件哈希、字体指纹与已登记的随附文件、三个宽度的渲染、隐藏目录素材复制和完整构建。
无需作者的 Vault。
`releases/` 中生成完整 ZIP、`manifest.json` 与 `SHA256SUMS`。
ZIP 使用 UTF-8 文件名，中文资源可跨系统解压；相同输入会生成相同的 ZIP。

# 两种主题来源

普通用户默认使用插件内部的 `templates/`。
开发者在设置中选择库内主题，通过现有 Vault 索引读取可编辑主题。
两者共用文章、字体、复制和导出的渲染逻辑。
发布快照按 `theme_id` 定位，不按作者本机目录名定位。

公开快照可以由已审阅的主题正本导出：

```bash
node scripts/export-templates.mjs --source "/path/to/ApprovedThemes" --target "/path/to/NewEmptySnapshot"
```

导出保留源 manifest 的字体文件、family、覆盖表与字体规则，核对原文件指纹。
它复制登记的运行素材、组件和字体，不复制历史文章或旧样张。
原始许可与说明按已有文件保留，不自动换字体或生成授权声明；主题视觉规范和介绍图完成审阅后再同步。

文心喜乐的特定原字库有 4 个字形编码不能被 Chromium 正常绘制。
导出时仅对已核对 SHA-256 的该字库生成同家族兼容文件，逐字验证全部轮廓、字符映射和字宽不变；原字库与覆盖表一并保留。
兼容覆盖表排除原本没有轮廓的非空白字符，由模板已登记的备用字体接管。
原始来源、派生文件和验证报告登记在 `fonts[].compatibility`。
此导出步骤需要 Python 环境的 `fonttools[woff]==4.65.0`，可用 `WECHAT_MP_FONT_PYTHON` 指定解释器；正常构建和安装直接使用已登记文件，无需 Python。

更新模板文件后，运行以下命令重建资源清单，再运行完整检查：

```bash
node scripts/refresh-template-catalog.mjs
npm run check
```

# 介绍图

`manifest.json` 的 `showcase_image` 指向模板介绍图，与 `preview_image` 分开。
`showcase_status: "draft"` 会在设置页标为「视觉样张（待确认）」。
没有介绍图时显示已登记的预览图；两者都没有时显示待补充说明。
禁止用占位图冒充验收完成的作品。

# 发版

1. 同时更新 `package.json`、`package-lock.json` 和 `plugin/manifest.json` 的版本。
2. 更新 `3. 版本记录.md`，完成 `npm run check`。
3. 在独立测试 Vault 验证加载、模板切换、复制、导出和已有配置升级。
4. 运行 `npm run package`，核对 ZIP 和校验和。
5. 推送源码后，为同一提交建立版本标签与 GitHub Release，附上完整 ZIP、`manifest.json`、`SHA256SUMS`。

发布前完成本地自动检查，再由维护者主动上传版本；当前仓库未启用 GitHub Actions。
